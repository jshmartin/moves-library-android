# Cypher

Cypher is an Android app for breakers (breakdancers) who film their training. It keeps a personal library of your moves, links your videos to them, chains moves into combos, and runs and logs your practice sessions.

It's built for one dancer on one phone. There are no accounts, no server and no sync. Your data stays in a database on the device, and your videos stay wherever they already are.

## What's in the app

### Library

Your moves, grouped into categories. Cypher starts with five categories (Toprock, Go-downs, Footwork, Power, Freezes) that you can rename, reorder or delete.

Each category also starts with its foundation moves, 25 in all, such as the Indian step, knee drop, 6-step, windmill and baby freeze. Each one has a one-line note on how it goes. They're ordinary moves set to Learning, so you can edit or delete any of them and add your own. The list is in `data/StarterMoves.kt`.

Libraries created before the starter moves existed get them once, when the app updates. A starter move is skipped if you already have a move by that name, ignoring case, spacing, punctuation and a trailing "s" (so "Six Step" counts as the 6-step), or if you renamed or deleted its category. Your existing moves aren't changed.

Each move has a status (Learning, In arsenal or Battle-ready), notes and videos. A move can also be a variation of another move, such as a 3-step under a 6-step.

To add a move, name it, pick its category and status, and attach videos from your device or the video library if you have them. Adding from a category's screen picks that category for you. Notes are added later, by editing the move.

### Videos

Every video you've added, and where each one is linked. A video is filed under at most one move or set, and can also be attached to any number of practices and logged sessions. The video most recently linked to a move or set is its "top" video.

### Sets

A set is a combo: an ordered chain of moves, where the same move can appear more than once. **Play combo** plays each move's top video back to back in chain order. If a top video's file is gone it plays that move's next video instead, and it tells you which moves were swapped or had nothing to play.

**Randomize a set** stacks moves from your library into a new combo of 2 to 10 moves. Its rules work like this:

- **Stages come from category names.** Each move's stage is read from its category's name: toprock, go-down, footwork, power or freeze. Renamed categories such as "Uprock" or "Drops" still count. Moves in a category it can't place, such as "Tricks", are left out, and the screen says so.
- **A set goes down once and stays down.** It runs from standing down to the floor. Toprock leads into more toprock, a go-down or footwork, never straight into power or a freeze. Once you're on the floor, nothing leads back up to toprock or a go-down.
- **It usually opens standing and ends on a freeze.** Each stage is as likely as the rules say, however many moves it has.
- **It avoids repeats.** The same move never comes twice in a row and rarely twice in one set.
- **Your own transitions count a little extra.** A transition you've already chained in one of your own sets comes up a bit more often.

You can shuffle the whole set, swap one move for another that fits between its neighbours, or skip moves you're still learning. **Save as set** opens the new set in the editor, ready to rename and save. The rules are in `ui/sets/SetFlow.kt`.

**Basic sets** are common beginner combos built from the starter moves, such as the Indian step, knee drop, 6-step and baby freeze, or a coin drop into windmills that ends on a baby freeze. The Sets tab lists each one whose moves are all in your library, matched by name the same way the starter moves are. Tap one to open it in the editor and save it. Once you have it, under that name or as the same chain of moves, it drops off the list. The list is in `data/BasicSets.kt`, and basic sets aren't stored until you save one.

### Practice

A practice is a saved training plan made up of:

- An ordered list of drills. A drill is a move from the Library, a set from Sets, or a named block such as a warm-up.
- Target sets and reps for each drill.
- A boxing-style round timer with a number of rounds, a work time and a rest time.

You can start a saved practice, or start a **Quick practice** to run the timer without a plan. During a session:

- The timer gives you a 10-second get-ready, a bell to start each round and three bells to end it, a warning 10 seconds before a round ends, and countdown ticks. You can pause, skip or reset it. The sounds are generated by the app and play over whatever music is on.
- You count reps, finish sets, undo mistakes, add drills on the fly and watch a drill's video.
- The screen stays on.

Every count is saved as it happens. If the app gets killed mid-session, the Practice tab offers to resume the session or save it to your log.

The **Log** tab shows each finished session's drills, sets and reps, time practiced, notes and videos, plus weekly and all-time totals. A log entry stays readable after the practice, move or set it came from is deleted.

> **"Sets" means two things.** A set in the Sets tab is a combo of moves. Sets and reps in Practice are training sets. The app labels drills "From Sets" and "From Library" to keep them apart.

## How videos are handled

Cypher never copies, moves or changes your video files, and removing a video from the app leaves the file alone. For each video it stores a reference to the file, its name, size and duration, and a fingerprint (a SHA-256 hash of the file's size and its first and last 1 MiB).

If a file is moved or deleted, the app marks it as missing and keeps the entry and all its links until you remove it. There are four ways to reconnect it:

- **Automatically.** Once you've given the app media permission, it looks for missing files whenever a list of videos opens or the app comes back to the front, and relinks any it finds.
- **Search the device.** The app looks through the device's media index for a file of the same size and fingerprint. This is the only feature that asks for media permission.
- **Locate it.** You pick the file yourself, from the Videos tab or from the move, set, practice or log it's on. If its content doesn't match, the app asks before relinking.
- **Add it again.** A picked file whose content matches a missing entry relinks that entry and keeps its links.

A file that's really been deleted can't be brought back, because the app only stores a reference to it.

## Backup and moving phones

Your moves, sets, practices, logs and video links are only stored in the app's database on the phone. Uninstalling the app or clearing its storage erases them, though your video files aren't affected. The app says so on first launch and offers to set up a backup. Android's own cloud backup stays turned off, so nothing leaves the phone unless you send it.

**Backup & transfer**, in the Library tab's menu, has three parts:

- **Automatic backup.** You pick a folder, such as Documents, and the app keeps `cypher-backup.db` there. The file updates a few seconds after each change and survives uninstalling the app. If the folder you pick already holds a backup, for example after a reinstall, the app asks whether to restore it or replace it. It never overwrites one without asking.
- **Restore.** You pick a backup file, the app shows what's in it, and everything in the app is replaced. You can undo a restore straight after.
- **Move to a new phone.** **Send backup** hands a fresh backup file to the share sheet, so Quick Share can send it to the new phone without the internet. You then restore it there.

A backup file is a copy of the database, so a backup from an older version of the app is upgraded through the same migrations when it's restored. The app refuses backups from a newer version. Video files aren't in the backup. On restore, any video whose file the app can't open and confirm by its fingerprint is marked missing, so it's relinked automatically or through **Search device** rather than pointing at a different file that now sits at its old address.

## Tech stack

| Area | Choice |
| --- | --- |
| Language | Kotlin |
| UI | Jetpack Compose with Material 3 |
| Navigation | Navigation Compose, in a single activity |
| Storage | Room (SQLite) |
| Video playback | Media3 ExoPlayer |
| Android versions | Minimum Android 7.0 (API 24), target API 37 |

Each screen is a composable backed by a `ViewModel`. ViewModels expose `StateFlow`s built from Room `Flow` queries, so the UI updates itself when the data changes. There's no dependency injection framework: ViewModel factories get the database from `BreakingApp`.

## Building

You'll need Android Studio with Android SDK Platform 37, and an emulator or device running Android 7.0 or later.

Open the project in Android Studio and run the `app` configuration, or use Gradle from the command line. On Windows, use `gradlew.bat` in place of `./gradlew`.

Build a debug APK, which goes to `app/build/outputs/apk/debug/`:

```bash
./gradlew assembleDebug
```

Install it on a connected device:

```bash
./gradlew installDebug
```

## Testing

Unit tests cover the round timer, practice formatting, variation grouping, the starter move list, the set randomizer's rules, the basic sets, the video model's rules, how the player falls back when a file is missing and how a backup's contents are described:

```bash
./gradlew testDebugUnitTest
```

Instrumented tests cover the DAOs, video links, relinking moved or deleted files, adding the starter moves, adding and editing moves, backing up and restoring, and database migrations:

```bash
./gradlew connectedDebugAndroidTest
```

> **Warning:** Gradle uninstalls the app after an instrumented test run, which erases its database. Run these tests on an emulator, not on a phone with real data. If a phone is also connected, set `ANDROID_SERIAL` to the emulator's serial so Gradle leaves the phone alone.

## Changing the database

The database is defined in `app/src/main/java/com/example/myapplication/data/AppDatabase.kt`. It holds real training history, so schema changes must preserve data. When you change an entity:

1. Increase `version` in `AppDatabase`.
2. Add a migration to `AppDatabase.MIGRATIONS`. Backup files are opened with the same list, so older backups keep restoring.
3. Commit the new schema file Room generates in `app/schemas/`.
4. Add a case to `AppDatabaseMigrationTest`.
5. If you added a table, add it to `BackupManager.WATCHED_TABLES` so changes to it trigger a backup. A test fails until you do.
